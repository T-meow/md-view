# 安全反馈 / Security reports

请使用最新正式版复核问题。不要在公开 Issue 中发布私人文档、凭据或可直接利用的漏洞细节。

如果仓库的 Security 页面提供 **Report a vulnerability**，请通过该入口私密报告。若入口不可用，请先创建仅请求私密联系方式的 Issue，不附上漏洞利用细节。报告应说明受影响版本、操作系统、触发条件和影响；最小复现材料应去除个人信息。

项目由个人维护，不承诺固定响应或修复时限。安全反馈不改变“不接受 PR”的维护规则。

## English

Check the latest stable release before reporting. Do not post private documents, credentials, or actionable exploit details in public issues.

Use **Report a vulnerability** on the repository's Security page when available. Otherwise, open an issue requesting a private contact channel without exploit details. Include the affected version, OS, trigger, impact, and a minimal reproduction with personal information removed.

This is an individually maintained project without a guaranteed response or fix timeline. Security reports do not change the policy of not accepting pull requests.
